FileVault Backend Architecture & REST Contract

Production decoupled architecture specification

// PRODUCTION STORAGE ARCHITECTURE

[Browser Client] 
      │ (Vanilla JS / Fetch API / multipart/form-data)
      ▼
[REST API Gateway] <─── CORS & JWT/Rate-limit Check
      │
      ├──────────────────────────────┐
      ▼                              ▼
[PostgreSQL / MySQL]           [Object Storage (S3 / MinIO / GCS)]
- id (UUID)                    - /uploads/:id/:hash-:filename
- filename, mime_type          - Content-Disposition: attachment or inline
- file_size, storage_path      - High-speed CDN caching edge
- download_count, created_at

Contract Endpoints

GET /api/files Returns: List of public files metadata
POST /api/files/upload multipart/form-data (Key: file)
GET /api/files/:id Returns: Specific file metadata
DELETE /api/files/:id Removes file asset and metadata
GET /api/stats Total file count, size bytes, downloads

Connecting Your Backend Server

Open the browser console or inspect the JavaScript block. The client provides a unified singleton: FileVaultAPI.setBaseUrl('https://api.yourdomain.com/api'). If the remote server is unreachable, the frontend automatically falls back to client demo mode so you can test all UI workflows seamlessly.
